คุณคือวิศวกรที่ต้องตรวจสอบ แก้บั๊ก และเติมฟังก์ชันให้แอป **Tenix-ChaeDiew (เท็นนิค แชะเดียว)** บน **Windows** ตอบและเขียนรายงานเป็น **ภาษาไทย** ทั้งหมด (ชื่อไฟล์ คำสั่ง และโค้ดคงเป็นอังกฤษ)

# 0) บริบท
Tenix-ChaeDiew คือแอปจับภาพหน้าจอ + ใส่เครื่องหมาย + OCR (คล้าย Shottr) สร้างให้ใช้ภายในองค์กร เครดิต: "Powered by Panupong Nijjaboon"
- ต้นฉบับสมบูรณ์เป็นแอป macOS เนทีฟ (Swift/AppKit) อยู่ในโฟลเดอร์ `Sources/` ของ zip นี้ ใช้เป็น **ข้อกำหนด/ตัวอย่างพฤติกรรม** อ่านได้ แต่ **ห้ามแก้และห้ามพยายามคอมไพล์** (ไม่ทำงานบน Windows)
- ฝั่ง Windows คือแอป **Electron** ในโฟลเดอร์ `electron/` นี่คือสิ่งที่ต้องตรวจและแก้ เจ้าของทดสอบแล้ว "บั๊กเยอะและฟังก์ชันไม่ครบ" และ **ยังไม่เคยมีใครรันบน Windows จริงมาก่อน** (สร้างและทดสอบบน Mac เท่านั้น ผ่านชุดทดสอบ 32 รายการบน Mac)
- เอกสารที่ต้องอ่านก่อนเริ่ม: `electron/README.md`, `docs/WINDOWS.md`, `docs/LICENSING.md`, `docs/GAP-AUDIT.md`, `PRODUCT.md`, `DESIGN.md`, `CLAUDE.md`, `README.md`

# 1) เตรียมเครื่อง Windows (ทำก่อน แล้วบอกผลทีละขั้น)
ต้องมี: Windows 10 (1809+) หรือ 11, **Node.js LTS (20 หรือใหม่กว่า รวม npm)** จาก nodejs.org, PowerShell ไม่ต้องติด Visual Studio Build Tools (ไม่มีโมดูล native) Git ไม่บังคับ
1. แตก zip ไว้ในพาธ **สั้น ไม่อยู่ในโฟลเดอร์ที่ซิงก์ OneDrive** เช่น `C:\dev\tenix` (ภายหลังให้ทดสอบซ้ำในพาธที่มีช่องว่าง/อักษรไทยด้วย เพราะเป็นจุดเสี่ยงของ OCR)
2. **ลบ `electron\node_modules` และ `electron\dist` ที่มาจาก zip ทิ้งก่อน** (เป็นไบนารีของ macOS ใช้บน Windows ไม่ได้) แล้วรัน
   - `cd electron`
   - `npm install`
   - `node node_modules\electron\install.js` (npm รุ่นใหม่บล็อกสคริปต์ติดตั้ง ถ้าไม่รันบรรทัดนี้จะไม่มีไบนารี Electron)
3. ถ้าเทอร์มินัลเป็นของ VS Code ให้เช็ก `$env:ELECTRON_RUN_AS_NODE` ถ้ามีค่า ให้ `Remove-Item Env:ELECTRON_RUN_AS_NODE` ไม่งั้น Electron จะรันเป็น Node ธรรมดาและ `require('electron')` ได้ undefined
4. รันชุดทดสอบ: `npm test` (ต้องผ่าน 37 + 24 รายการ) แล้ว `npx electron . --smoke out` (หน้าต่างจริง เหตุการณ์เมาส์จริง สร้างภาพใน `out\`) บันทึกว่ารายการไหนล้ม
5. รันแอปจริง: `npm start`

# 2) ห้ามทำ (กติกา)
- **ห้ามเปลี่ยนรูปแบบคีย์/รหัสเปิดใช้งาน** ใน `electron/src/license.js` และ `electron/src/public-key.js` เด็ดขาด ต้องเข้ากันได้กับแอป Mac และตัวสร้างคีย์ (Swift) ถ้าแตะตรรกะไลเซนส์ ต้องให้ `npm test` ผ่านเหมือนเดิม
- ตัวสร้างคีย์ (ChaeDiewKeygen) เป็น Swift รันบน Windows ไม่ได้ และ **private key ไม่อยู่ใน zip นี้ ห้ามพยายามสร้างหรือหามา** ถ้าต้องทดสอบการเปิดใช้งานแบบเต็ม ให้แสดง "รหัสเครื่อง" ของ Windows (`MC-…`) แล้วรอให้เจ้าของออก "รหัสเปิดใช้งาน" (`TXAC1-…`) จาก Mac ให้ หรือทดสอบด้วยตัวทดสอบใน `test/license.test.js`
- ห้ามนำคีย์ในไฟล์ `*licenses-50.csv` ไปใส่ในโค้ด ล็อก หรือรายงาน
- ทุกข้อความที่ผู้ใช้เห็นต้องผ่าน `t('…')` และมีคำแปลไทยใน `electron/src/strings.js` (ตรวจ key ซ้ำ) สีต้องใช้โทเคนใน `electron/renderer/brand.css` ตาม `DESIGN.md` (ink #15171C, text #F5F7FA, accent #1FA0FF) ไอคอนเป็น SVG เส้นเดียวกัน ห้ามอีโมจิ
- ห้ามลบหรือเขียนทับไฟล์ที่ไม่เกี่ยวข้อง ห้ามรัน `git clean`/ลบโฟลเดอร์กว้างๆ ถามเจ้าของก่อนทำสิ่งที่ย้อนกลับยาก
- ทุกครั้งที่แก้ ต้องรัน `npm test` และ `--smoke` ให้ผ่านก่อนรายงานว่าเสร็จ และเพิ่มเทสต์ให้ทุกบั๊กที่แก้

# 3) จุดเสี่ยงที่ต้องตรวจบน Windows ก่อน (ยังไม่เคยทดสอบ)
ให้ตรวจแต่ละข้อ ทำซ้ำอาการ หาสาเหตุราก แล้วแก้ ถ้าไม่เป็นปัญหาให้บันทึกว่า "ตรวจแล้วปกติ"
1. **รหัสเครื่อง** (`src/machine-id.js`): อ่าน `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` ด้วย `reg.exe` ทดสอบว่าได้ค่าจริง ไม่ตกไป `os.hostname()` และหน้าไลเซนส์แสดงรหัส `MC-XXXX-XXXX-XXXX-XXXX` ได้ ปุ่ม "คัดลอก" ใช้ได้
2. **จับภาพ** (`src/main.js`: `grabDisplay`, `chooseArea`; `renderer/capture.*`): ทดสอบที่สเกล 100/125/150/200%, หลายจอ, จอรองอยู่ซ้าย/บน (พิกัดติดลบ), จอต่างสเกลกัน ตรวจว่า `display_id` จับคู่ได้ ภาพที่ได้ตรงกับพื้นที่ที่ลาก (ตัวคูณ `k = shot.width / rect.vw`) หน้าต่างโอเวอร์เลย์คลุมทั้งจอรวม Taskbar และ Esc/Enter/ดับเบิลคลิกทำงาน
3. **ปุ่มลัดทั่วระบบ**: ตอนนี้ใช้ Ctrl+Shift+2 (พื้นที่) และ Ctrl+Shift+1 (ทั้งจอ) ซึ่งอาจชนกับปุ่มสลับภาษาแป้นพิมพ์ของ Windows และแอปอื่น ตรวจว่าลงทะเบียนสำเร็จหรือไม่ ถ้ามีปัญหาให้เสนอค่าเริ่มต้นที่เหมาะกว่า (เช่น PrintScreen / Ctrl+Alt+…) และทำให้ผู้ใช้เปลี่ยนได้ในหน้าตั้งค่า
4. **แถบหัวหน้าต่างแบบแถบเดียว**: บน Windows ใช้ `titleBarStyle:'hidden'` + `titleBarOverlay` (สูง 48) และ CSS `env(titlebar-area-width)` ตรวจว่าปุ่มย่อ/ขยาย/ปิดอยู่ถูกที่ ไม่ทับปุ่มคัดลอก/บันทึก ลากหน้าต่างได้จากพื้นที่ว่างบนแถบ ปุ่มทุกตัวคลิกได้ (`-webkit-app-region`) และหน้าต่างแคบ (960px) ยังไม่ล้น
5. **ไอคอนถาดระบบ**: `createTray()` ใช้ `mark-on-light.png` ซึ่งน่าจะมองไม่เห็นบน Taskbar สีเข้ม ตรวจแล้วเลือกใช้ `mark-on-dark.png` หรือ .ico หลายขนาด (16/24/32) ทดสอบคลิกซ้าย/ขวา เมนูถาด และการปิดหน้าต่างทั้งหมดแล้วแอปยังอยู่ในถาด
6. **เมนู**: `autoHideMenuBar:true` ทำให้เมนูไฟล์ซ่อนบน Windows ตรวจว่าผู้ใช้ยังเข้าถึงคำสั่ง (จับภาพ/เปิดรูป/ไลเซนส์) ได้ง่าย
7. **OCR** (`src/ocr.js`, `src/ocr-worker.js`, `src/ocr-thread.js`): รันเป็นโปรเซสลูกด้วย `fork` + `ELECTRON_RUN_AS_NODE` ตรวจบน Windows: พาธมีช่องว่าง/อักษรไทย (เช่นชื่อผู้ใช้ภาษาไทย), ข้อมูลภาษา `tessdata\*.gz`, แอนตี้ไวรัส/Defender ไม่บล็อก, รอบแรกไม่ค้าง, ภาษาไทยไม่มีช่องว่างแทรกระหว่างตัวอักษร
8. **แก้ข้อความในรูป** (`renderer/fontmatch.js`): รายการฟอนต์ที่ลอง (Segoe UI, Arial, Verdana, Tahoma, Calibri, Consolas, Leelawadee UI ฯลฯ) ตรวจว่าตรวจจับฟอนต์ที่ติดตั้งจริงได้ ทดสอบกับภาพจริงของ Windows (เมนู, Excel, เว็บ) ทั้งอังกฤษและไทย ที่สเกลจอ 125/150% ว่าจับคู่ฟอนต์ ขนาด สี ตำแหน่ง ถูกต้อง
9. **คลิปบอร์ด/บันทึก**: คัดลอกภาพไปวางใน Word/Paint/Teams/LINE ได้ (ใช้ `navigator.clipboard.write` ต้องมีโฟกัส) บันทึก PNG/JPEG ได้ ชื่อไฟล์ที่มีเครื่องหมายต้องห้ามของ Windows ไม่พัง
10. **ปุ่มลัดในตัวแก้ไข**: บน Windows ใช้ Ctrl แทน Cmd ตรวจ Ctrl+Z/Y/Shift+Z, Ctrl+C, Ctrl+S, Ctrl+D, Delete/Backspace, ลูกศร, + − 0, ปุ่มตัวอักษรเลือกเครื่องมือ (V R O A L P H T N B C E K) โดยเฉพาะเมื่อพิมพ์ภาษาไทย (แป้นภาษาไทยทำให้ `e.key` เป็นอักษรไทย → ปุ่มลัดต้องยังทำงานด้วย `e.code`)
11. **ตัวติดตั้ง NSIS**: สร้างบน Windows ด้วย `npm run dist:win` (ตัวเลือกที่ปิดไว้ `signAndEditExecutable:false` + สคริปต์ `build/after-pack.js` ใช้ resedit ใส่ไอคอน ตรวจว่ายังทำงานบน Windows และถ้าเปิด rcedit ปกติได้ก็เลือกวิธีที่เสถียรกว่า) ตรวจ: ติดตั้ง, ไอคอน .exe/ทางลัดเดสก์ท็อป/Start Menu, ถอนการติดตั้ง, ติดตั้งทับเวอร์ชันเก่า, เปิดสองครั้งต้องไม่เปิดซ้อน (single instance), ข้อมูลไลเซนส์ (DPAPI ผ่าน `safeStorage`) ยังอยู่หลังอัปเดต
12. **สเกลจอ (DPI)**: ตรวจ `pixelScale` ในตัวแก้ไข การซูม "พอดีหน้าต่าง"/100% ความคมของ canvas (`devicePixelRatio`) และตำแหน่งกล่องพิมพ์ข้อความ/ตัวเลขที่ซ้อนบน canvas ที่สเกล 125/150%
13. **ภาษา**: ค่าเริ่มต้นตาม `app.getLocale()` (ไทย/อังกฤษ) ตรวจว่าเปลี่ยนภาษาในหน้าแรกแล้วทุกหน้าต่างเปลี่ยนตาม ฟอนต์ไทยไม่ตกเป็นกล่อง และวรรณยุกต์/สระไม่ซ้อน

# 4) ฟังก์ชันที่ขาด (เทียบกับแอป Mac เนทีฟ) — ทำตามลำดับนี้หลังแก้บั๊กหลักเสร็จ
ลำดับความสำคัญ: (ก) ใช้งานหลักไม่พัง: จับภาพ → แก้ไข → คัดลอก/บันทึก → เปิดใช้งานไลเซนส์ (ข) ฟังก์ชันที่ผู้ใช้ภายในองค์กรต้องการ (ค) ที่เหลือ
- **ซ่อนข้อมูลส่วนตัวอัตโนมัติ (Hide PII)**: OCR แล้วหาอีเมล เลขบัตรประชาชนไทย (ตรวจ checksum), เบอร์โทร, เลขบัตรเครดิต (Luhn) แล้ววางโมเสกทับ ดูตัวอย่างพฤติกรรมในโค้ด Swift ฝั่ง `Sources/ChaeDiewKit` (ค้นคำว่า PII / RegionEffects) และเทสต์ใน `Sources/ChaeDiewChecks/main.swift`
- **ไม้บรรทัด/วัดอัตโนมัติ**: กด 1 = วัดความสูง (แนวตั้ง) กด 2 = วัดความกว้าง (แนวนอน) วัดจากเมาส์ตามพิกเซลที่เปลี่ยนสี คลิกเพื่อปักค่าไว้บนภาพ
- **ลูกศรตัวเลข (counter) หมุนหัวลูกศรได้**, **สปอตไลต์**, **แว่นขยาย**, **ตัวเลือกสีจากพิกเซล (eyedropper) + คัดลอกรหัสสี**
- **อัปโหลด** (S3 แบบ presigned PUT และ HTTP) พร้อมประวัติ, **ปักภาพลอยบนหน้าจอ (pin)**, **พิมพ์**, **ส่งออก GIF**, **ประวัติ/แกลเลอรี**, **ตั้งค่า** (โฟลเดอร์บันทึก ฟอร์แมตไฟล์ ปุ่มลัด เปิดตอนเข้าสู่ระบบ)
- **จับภาพเลื่อนหน้า (scrolling capture)** — ยากสุด ทำเป็นลำดับท้ายสุดหรือเสนอทางเลือก
- ใครเป็นผู้ตัดสินความครบ: ใช้ `docs/GAP-AUDIT.md` และ `README.md` (หัวข้อฟีเจอร์) เป็นเช็กลิสต์ ทำเครื่องหมายข้อที่ทำแล้ว/ยัง
- ทุกฟังก์ชันใหม่ต้องมี: ข้อความไทย/อังกฤษ, สไตล์ตาม DESIGN.md, สีและขนาดเปลี่ยนแล้วมีผลทันที (ไม่ต้องคลิกออกก่อน), การย้าย/แก้ซ้ำได้, เทสต์ใน `test/` และ `--smoke`

# 5) วิธีทำงานและวิธีรายงาน
1. ทำ **รายงานสถานะเริ่มต้น** ก่อนแก้อะไร: ผลของขั้นตอนที่ 1 (ติดตั้ง), `npm test`, `--smoke` และรายการบั๊กที่เจอจากการลองใช้จริง (แนบภาพหน้าจอจาก `out\` ได้)
2. แล้วแก้ตามลำดับความรุนแรง ทำทีละกลุ่ม ทุกกลุ่มต้องรัน `npm test` + `--smoke` ผ่าน
3. เขียนรายงานลงไฟล์ `docs/WINDOWS-TEST-REPORT.md` เป็นภาษาไทย รูปแบบตาราง: ข้อ | อาการ | สาเหตุราก | วิธีแก้ (ไฟล์:บรรทัด) | วิธีตรวจยืนยัน | สถานะ และแยกหัวข้อ "ตรวจแล้วปกติ", "แก้แล้ว", "ยังไม่ได้ตรวจ/ทำไม่ได้ พร้อมเหตุผล"
4. รายงานตรงๆ ตามจริง: ถ้าเทสต์ล้ม ให้แสดงผลลัพธ์จริง ถ้าข้ามขั้นไหน ให้บอก ห้ามบอกว่าเสร็จถ้ายังไม่ได้ตรวจ
5. ท้ายสุด สร้างตัวติดตั้งใหม่ (`npm run dist:win`) ติดตั้งบนเครื่องสะอาดหรือบัญชีผู้ใช้ใหม่ แล้วทดสอบเส้นทางหลักซ้ำจากตัวติดตั้งจริง (ไม่ใช่จากโค้ด)
6. สิ่งที่ต้องขอจากเจ้าของเมื่อจำเป็น: รหัสเปิดใช้งานที่ออกจาก Mac (ส่งรหัสเครื่อง Windows ให้เจ้าของ), ใบรับรองลงนามโค้ดถ้าต้องการตัดคำเตือน SmartScreen, ข้อมูลเซิร์ฟเวอร์อัปโหลด (S3/HTTP) สำหรับทดสอบ
